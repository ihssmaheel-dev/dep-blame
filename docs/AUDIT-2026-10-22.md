# Dependency history audit and graph redesign

Date: 2026-10-22. Baseline: `984f4aca9864970a3b103b6b0c949a692ebe0e72`.

## Scope and concept

dep-blame explains dependency additions, updates, removals, section moves and recorded resolution changes from local Git history. The graph is scoped to one dependency and one manifest. It includes commits that changed dependency evidence. It is not a general Git browser, dependency installer, security scanner or CI dashboard.

This review examined the scanner and Git readers, npm/pnpm/Yarn/Bun parsers, cache stores and locking, flow provenance, CLI/export paths, local HTTP and hosting integration, dashboard state handling, graph interaction, packaging and tests. Findings below were fixed and checked with real Git fixtures where applicable. This is an engineering review, not a guarantee that every possible defect has been eliminated.

## Findings and fixes

| Priority | Finding | Resolution and verification |
| --- | --- | --- |
| High, correctness | Nested pnpm/Bun importers were interpreted relative to the repository root. Events and HEAD resolutions could be attached to the wrong manifest. | Resolve importer paths relative to the lockfile. Identical blobs retain separate workspace identities. Cold/warm Git regressions cover two folders and a one-workspace update. |
| High, correctness | A missing importer or resolution could become a false absence or a declared range displayed as a resolved version. | Missing importer evidence is unavailable. Incomplete pnpm/Bun resolutions fail conservatively with a warning and retain last-good history. Tests cover incomplete records and HEAD queries. |
| Medium, correctness | Parser cache keys did not distinguish lockfile formats. | Keys include format and parse mode. Shared byte content cannot reuse another format's result; regression verifies npm and Bun interpretations. |
| Medium, correctness | npm workspace metadata outside node_modules could contaminate installed version sets. | Only installed package paths contribute. A fixture with a same-named workspace and installed package preserves the actual installed version. |
| Medium, memory | A single oversized parsed lockfile remained cached beyond the entry budget; huge version strings bypassed entry counting. | Oversized results are not cached. Retention is bounded by 64 results, 100,000 entries, and a 16 MiB estimated content budget. Tests cover entry count and string size. These are retention estimates, not an exact RSS cap. |
| Medium, responsiveness | Every compressed response used synchronous gzip, including repeated static assets. Encoding quality zero was ignored. | Async gzip, reuse of compressed static buffers, q=0 handling and Vary on compressed and identity responses. HTTP regressions cover new assets and negotiation. |
| Medium, API consistency | Bounded API queries could rerun scans between pages and silently accept malformed pagination. | Pages, months and facets reuse a captured generation. Explicit Sync refreshes it. Stale generations return 409; invalid offsets/limits return 400. A commit added between requests cannot silently change the captured page. |
| Medium, identity integrity | In-flight hosting work could return the previous host's account after the repository remote changed. | Detection, account responses, rate limits and cache writes check the remote generation. A delayed transport regression switches hosts during lookup and verifies only the new identity is retained. |
| Medium, graph UX | Merge integrations were moved into a separate disclosure, losing their visible ancestry position. The list offered no canvas navigation. | A directed graph keeps branches and merge integrations together. Continuation and incoming integration connections are distinct. Only verified model edges are rendered. |
| Medium, graph UX | Flow could default to a different workspace than the clicked event; off-window later connections were not exposed. | Table/calendar entries pass their exact owning manifest. The inspector links earlier and later recorded connections, including other windows. |
| Medium, failure handling | A renderer failure could leave visible, unpositioned cards. | Failures hide the graph and show a retry/error state. Regression covers initialization failure. |
| Low, responsive UI | Header actions overflowed the page at narrow mobile widths. | Actions wrap; verified at 390 px with document scroll width equal to its client width. |
| Low, cleanup | Completed DNS lookups retained timeout timers; graph work was only aborted after server closure. | Clear DNS timers on settlement and abort builders before waiting for closure. |
| Low, documentation | Offline claims conflicted with enabled profile/avatar requests; test counts and bundle budgets were stale. | Clarify local history versus hosting requests; document the offline switch, graph controls, API generations and current limits. |

Cache schema is now **9**. Existing caches rebuild once so incorrect workspace attribution and incomplete resolution records are not carried forward. Public JSON remains `schemaVersion: 1`. Package version remains 0.3.0 until a separate release.

## Graph design

- Black dark-mode surfaces, existing light theme, restrained status colors, consistent cards, source labels, curved directed connections and a dotted canvas.
- Actual dependency ancestry sets layout order. Dates are labels, not inferred connections. Merge integrations keep their place in the graph.
- Dashed edges mean verified incoming parent state; solid edges mean matching previous recorded state. Equal version strings alone never create an edge.
- Drag or scroll to pan; Ctrl/Command + scroll zooms around the pointer. Fit, Focus and the minimap support navigation. Arrow keys pan the focused canvas; Left/Right and Home/End navigate focused change cards.
- Full evidence remains in the inspector when previews are truncated. Hide details expands the graph. Narrow screens stack the inspector below it. The compact Flow header leaves more space for the canvas.
- Loading, unavailable evidence, missing scripts, stale generations, empty windows and aborted requests have explicit states. Workspace filters use the shared custom popup.
- UI windows contain at most 50 commits, with an API cap of 100. Window controls appear only when more history exists. The calendar has no event pager.
- Layout is calculated once per window. Pan/zoom updates one transformed layer in `requestAnimationFrame`; it does not query Git or read each edge's DOM geometry. Observers, listeners and animation frames are cleaned up on replacement/close.

## Verification

- Baseline: 128 tests passed.
- Updated full suite: **141 passed, 0 failed, 0 skipped**, Windows / Node 22.23.2.
- UI/security/asset tests: **10 passed** after the responsive header fix.
- `npm audit`: **0 reported vulnerabilities**, including development dependencies. This checks known registry advisories, not every application-level security risk.
- Installed package smoke tests passed for normal and isolated `--omit=optional` installs: CLI bins, engine, API, CSP, bundled fonts, graph scripts/styles and LICENSE.
- The isolated installation without `yaml` preserved declaration history, warned about the missing optional parser, and did not invent resolved dependency events.
- Browser checks used a disposable repository with a real branch, merge, section move and second workspace. Checked selection, drag panning, Fit/Focus, keyboard navigation, workspace popup, collapsed details and responsive layout.
- Existing tests cover merges, corrupt snapshots, atomic cache promotion, CI ranges, terminal/CSV escaping, Host/Origin/Fetch-Site checks, avatar proxy restrictions, generation changes and stale asynchronous UI responses.

### Performance measurements

On this Windows / Node 22.23.2 machine, 300 runs of the pure 100-node layout produced approximately **0.29 ms median / 0.52 ms p95**. Dashboard HTML, scripts and styles transfer approximately **57 KiB gzipped**, within the 60 KiB gate. Fonts have a separate budget. No required runtime dependency was added.

These measurements exclude Git scanning, browser layout/painting, network latency and total process memory. They are not throughput guarantees for all repositories.

## Remaining boundaries

1. Git author metadata is not authenticated identity. Forge-linked accounts are optional lookups; unmatched accounts retain initials. No original author is inferred from an equal version or merge message.
2. Shallow, truncated, corrupt or missing Git/lockfile evidence limits completeness. Binary `bun.lockb` is unsupported; Yarn does not establish direct-dependency attribution.
3. npm workspace declarations are tracked. A shared npm lockfile reports root direct resolutions and aggregated installed version evidence; it does not resolve every workspace's full dependency tree. pnpm/Bun importers have explicit workspace attribution. A version set is not a proven workspace tree.
4. Incomplete Bun/pnpm resolution records are handled conservatively at the lockfile parse level. A warning can withhold other resolution events from that file until readable evidence returns; declarations remain independent.
5. Graph rendering and parser-cache retention are bounded. The dashboard still receives the full event result for global search, calendar and export, and the server retains that result. Overall storage and memory grow with history. Paginating those operations end-to-end remains a separate scalability task.
6. The server has no authentication. Loopback is the default; LAN binding and private forge access require explicit environment opt-ins. `DEP_BLAME_AVATARS=0` disables hosting requests. There is no telemetry or registry vulnerability scan.
7. Manual browser checks use the desktop app's Chromium browser. Other browser engines and real multitouch hardware were not exercised locally. Existing CI covers Node/OS combinations; local results alone do not establish that matrix.

## Release handoff

Restart running UI servers to load the new engine and assets. The schema-9 rebuild can make the first scan slower; subsequent reads reuse the corrected cache. Commit/push does not publish an npm version. Follow the existing tagged release process when ready to distribute the update.
